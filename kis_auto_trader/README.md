# kis_auto_trader

한국투자증권(KIS) API로 **일봉 데이터를 모으고, 그 위에서 전략을 검증하는** 프로그램입니다.
실제 주문은 내지 않습니다 — `api_client.py` 에서 주문 함수를 통째로 지워서
구조적으로 불가능합니다 (`tests/test_observation.py` 가 매번 그걸 확인합니다).

## 구조 (2026-09-13 개편)

```
universe.py       관찰할 종목 200개를 한 번 정해 universe.json 에 고정
      |
collect_daily.py  매일 장 마감 뒤 1회 실행 (daemon.py 가 자동으로 부름)
      |
panel.py          그 종목들의 일봉을 data/panel_YYYY.csv 에 쌓는다
      |
backtest.py       쌓인 일봉 위에서 팩터/보유기간/손절폭을 바꿔가며 돌려본다 (API 안 씀)
```

**왜 이렇게 바꿨나.** 이전 구조는 전략을 하나 정해 앞으로 굴려보는 방식이었는데,
그러면 손절 기준이나 보유기간을 바꿔볼 때마다 데이터를 처음부터 다시 쌓아야 했다.
실제로 쌓인 가상매매는 17건이었고 같은 종목 반복을 빼면 독립적인 판단은 11건이라
무엇도 판단할 수 없었다. 게다가 관찰 종목이 매일 "그날 많이 움직인 종목"으로 새로
뽑혀서, 4거래일 내내 등장한 종목이 6개뿐이었다.

고정된 종목들의 일봉만 쌓아두면 어떤 전략이든 같은 데이터에 다시 돌려볼 수 있다.
그리고 일봉은 과거치를 지금 당장 받아올 수 있어서, 한 달씩 기다릴 필요가 없다.

  백테스트의 미래정보 차단·손절 체결가, 유니버스 고정 —

- 200종목 × 5년(25만행) 규모에서의 동작/속도 — **검증 완료**
  (저장 1.5초, 파일 16MB, 24개 조합 스윕 11초)
- KIS 인증/현재가조회/일봉조회/잔고조회 — **실전 계좌로 검증 완료**
- Windows 작업 스케줄러 자동 실행 — **등록 및 수동 실행 검증 완료**
- **일봉 페이징 — 실전 계좌로 검증 완료 (2026-09-14)**. 11종목 × 12,427행,
  2021-01-04~2026-09-14. 종목당 1,397행으로 한 번에 100건이라는 상한을 넘겼고,
  신규 상장 종목은 상장일부터 정확히 시작했습니다(아로마티카 2025-11-27,
  샌즈랩 2023-02-15).
- **거래대금 순위로 유니버스 채우기 — 실전 계좌로 검증 완료 (2026-09-15)**.
  한 번에 54종목.
- 유니버스가 목표치(200종목)까지 실제로 차는지는 **아직 확인 중**. 거래대금
  상위는 날마다 종목이 비슷해서 중간에 멈출 수 있습니다 (그러면 목표를 실제로
  채워지는 수로 낮추거나 조회 조합을 늘려야 합니다).

## 1) 설치

```bash
pip install -r requirements.txt
```

## 2) API 키 발급 (본인이 직접 해야 함)

1. [KIS 개발자센터](https://apiportal.koreainvestment.com) 회원가입 (본인 명의 증권 계좌 필요)
2. "오픈API 신청"에서 **모의투자**, **실전투자** 둘 다 신청
   - 모의투자는 즉시 발급되는 경우가 많습니다
   - 실전투자는 계좌 확인 절차가 있을 수 있습니다
3. `.env.example` 을 복사해 `.env` 로 이름 바꾸고, 발급받은 App Key/Secret/계좌번호를 채우세요

```bash
cp .env.example .env
```

## 3) 설정 확인

`config.yaml` 을 열어보세요. 기본값은:

- 모드: `mock` (모의투자)
- 총투자금: 1,000,000원, 그중 90%를 네이버(035420)에 배정, 10%는 현금 버퍼
- 전략: 5일선/20일선 골든크로스 매수, 데드크로스 매도
- 손절: -5% (전략 신호와 무관하게 우선 적용)
- 최대 동시 보유 3종목

숫자만 바꾸면 되고, `watchlist` 에 종목을 더 추가할 수도 있습니다.

## 4) 최초 연결 점검 (반드시 순서대로)

실제 키를 넣은 뒤, 한 번에 다 돌리지 말고 아래 순서로 하나씩 콘솔에서 확인하세요.

```bash
python -c "from common import load_config; import auth; cfg=load_config(); print(auth.get_access_token(cfg)[:20], '...')"
python -c "from common import load_config; import api_client; cfg=load_config(); print(api_client.get_current_price(cfg, '035420'))"
python -c "from common import load_config; import api_client; cfg=load_config(); print(api_client.get_daily_prices(cfg, '035420')[-5:])"
python -c "from common import load_config; import api_client; cfg=load_config(); print(api_client.get_holdings(cfg))"
```

토큰 발급 -> 현재가 조회 -> 일봉 조회 -> 잔고 조회 순서로, 각 단계가 에러 없이 값을 반환하는지 확인하세요.
여기까지 `mode: mock` 상태로 확인하는 걸 권장합니다.

## 5) 실행

```bash
python main.py
```

`mode: mock` 이면 바로 실행됩니다.
`mode: real` 로 바꾸면 최초 1회 `REAL` 을 직접 입력해야 합니다 (실수 방지 안전장치).
이후 총투자금·종목 구성이 바뀌지 않는 한 다시 묻지 않으므로, 예약 실행으로 넘어갈 수 있습니다.

## 6) 매일 자동 실행 (Windows 작업 스케줄러)

**`자동실행 등록.bat` 을 한 번만 실행하면 끝입니다.** 그 뒤로는 매일 사람이 켜줄 필요가 없습니다.

등록되는 내용:
- 평일 08:50 에 `run_daemon_scheduled.bat`(= `daemon.py`) 자동 시작
- **15:50 까지 1시간 간격으로 재시도** - 08:50 에 컴퓨터가 꺼져 있었거나 절전 중이었으면
  그 다음 정시에 따라잡는다 (예전 방식은 그 시각을 놓치면 하루를 통째로 날렸다)
- 이미 돌고 있을 때 재시도가 걸려도 무해하다 - `daemon.py` 가 잠금 파일을 들고 있어서
  두 번째 인스턴스는 즉시 종료된다
- 주말은 `daemon.py` 가 스스로 판단해서 바로 종료한다

```bash
등록 확인:  schtasks /Query  /TN "KIS_DataCollect"
지금 실행:  schtasks /Run    /TN "KIS_DataCollect"
등록 해제:  schtasks /Delete /TN "KIS_DataCollect" /F
```

컴퓨터가 하루 종일 꺼져 있으면 그날은 당연히 수집이 안 됩니다. 평일엔 켜두는 게 제일 확실합니다.

콘솔 출력은 `logs/run_console.log` 에 남으니, 자동 실행이 잘 됐는지는 이 파일로 확인하세요.

참고: `자동매매 시작.bat` 은 마지막에 `pause` 가 있어서 사람이 직접 실행할 때만 쓰는 용도입니다
(예약 실행에 걸면 키 입력을 기다리며 영원히 멈춥니다). 예약용은 `run_daemon_scheduled.bat` 입니다.

## 7) 전략 검증하기 (백테스트)

패널이 쌓였으면 API 없이 언제든 돌릴 수 있습니다.

```bash
python panel.py                  # 지금 몇 종목 몇 년치가 쌓였는지
python backtest.py               # 팩터 4개를 기본 설정(20일 보유)으로 비교
python backtest.py --sweep       # 팩터 x 보유기간 x 손절 조합을 쓸어서 표로
python backtest.py --factor momentum --hold 20 --top 10 --stop -8
```

미래 정보를 안 쓰려고 지킨 것 (이게 틀리면 결과 전체가 무의미해집니다):

- 팩터는 재조정일 종가까지만 써서 계산
- 매수는 신호일 종가가 아니라 **다음 거래일 시가**에, 매도도 마찬가지
- 손절은 그날 저가가 손절선을 뚫었는지로 판단하고, 갭하락이면 손절선이 아니라
  그날 시가(더 불리한 쪽)로 체결된 것으로 계산

결과를 볼 때 같이 봐야 하는 것은 `backtest.py` 가 실행 끝에 매번 출력합니다.
요약하면: 표본 수는 거래 건수가 아니라 **기간 수**이고, 조합을 여러 개 돌리면
1등은 우연일 수 있으니 인접한 설정들이 같은 방향인지를 보고, 유니버스가
"2026년 9월에 거래가 활발했던 종목"으로 만들어졌다는 편향이 들어있습니다.

### 아직 못 하는 것

- **밸류 팩터 *과거* 백테스트** — PER/PBR 은 조회 시점 값만 받을 수 있어서 과거
  시계열이 없습니다. 그래서 `fundamentals.py` 가 오늘부터 하루 1회씩 기록합니다
  (`data/fundamentals_YYYY.csv`). 쌓인 기간만큼은 나중에 검증할 수 있습니다.
- **ROE/부채비율 등 퀄리티 팩터** — KIS API 범위 밖입니다. DART 오픈API 같은
  별도 출처가 필요합니다.
- **종목별 외국인·기관 순매수** — 현재가 조회 응답의 `frgn_ntby_qty` 는 실제로는
  거의 항상 0으로 들어옵니다(1,460행 중 1,448행). 전용 엔드포인트가 따로 필요합니다.
  대신 외국인 *지분율*(`hts_frgn_ehrt`)은 들어오므로, 매일 기록해두면 그 일별
  변화로 흐름을 간접 추정할 수 있습니다.

## 종목 선정 기준을 왜 바꿨나 (2026-09-14)

실제로 쌓인 10분 간격 장중 가격(4거래일, 92 종목-일)으로 확인한 결과:

| 날짜 | 감시종목 평균 | 코스닥 | 초과수익 |
|---|---|---|---|
| 9/4 | −0.73% | +1.34% | −2.06%p |
| 9/8 | −2.16% | −0.99% | −1.17%p |
| 9/9 | +1.05% | +0.40% | +0.65%p |
| 9/14 | −0.79% | +0.97% | −1.76%p |

09:30부터 장 마감까지 평균 **−1.03%**. 코스닥이 오른 날에도 지수 대비 뒤쳐졌습니다.

원인은 후보를 뽑는 출처였습니다. `screener._base_candidates` 는 "그날 등락률
상위/하위"에서 뽑는데, 그건 정의상 **그날 이미 크게 튄 종목**이고 튄 뒤에는
되밀립니다. 그런 종목을 사면 출구 규칙을 어떻게 바꿔도 진입 자체가 마이너스입니다.

그래서 `universe.py` 가 채우는 출처를 **거래대금/거래량 상위**로 바꿨습니다.
"오늘 얼마나 움직였나"가 아니라 "얼마나 크고 활발하게 거래되나"로 뽑힙니다.

유니버스는 한 번 차면 고정되므로, 종목마다 어느 출처에서 들어왔는지
`universe.json` 에 같이 적습니다 (`python universe.py` 로 출처별 집계 확인).
잘못 채워졌으면 `python universe.py --reset` 으로 다시 시작할 수 있습니다.

**(2026-09-15) 실전 계좌로 확인 완료.** 한 번 실행에 54종목이 들어왔고,
SK하이닉스·삼성전자·현대차·KB금융 같은 대형주와 알테오젠·HPSP·심텍 같은
중소형주가 섞였습니다 — 등락률 순위로 뽑을 때 나오던 급등락 소형주 쏠림이
사라진 것을 확인했습니다.

TR 조회가 실패하는 날에는 등락률 순위로 되돌아가면서 경고를 찍고, 그렇게 들어온
종목은 출처가 `등락률상위(대체)` 로 기록됩니다. `python universe.py` 로 출처별
집계를 확인할 수 있습니다.

## 생성되는 파일

- `data/panel_YYYY.csv` — **고정 유니버스의 일봉 (새 구조의 본체)**. 연도별로 나눠
  저장합니다. 한 파일에 다 넣으면 매일 수십 MB가 통째로 다시 커밋돼서 저장소가
  금방 불어나는데, 나누면 매일 바뀌는 건 올해 파일 하나뿐입니다.
- `data/fundamentals_YYYY.csv` — 일별 PER/PBR/외국인지분율 등. **과거치를 받아올
  수 없는 값**이라 하루 빠지면 그 하루는 영구히 빕니다.
- `universe.json` — 고정 관찰 종목 목록 + 종목별 출처. 손으로 더하거나 빼도 됩니다.
- `logs/decisions.csv` — 매일 각 종목에 대한 판단 기록 (매수/매도/관망 + 이유)
- `logs/trades.csv` — 실제로 나간 주문 기록
- `logs/run_console.log` — 예약 실행 때의 콘솔 출력 (`run_trader.bat` 이 남김)
- `token_cache.json` — 접근토큰 캐시 (재발급 남용 방지용, 공유 불필요)
- `real_mode_ack.json` — 실전투자 최초 확인 기록 (설정 변경 시 재확인 트리거)
