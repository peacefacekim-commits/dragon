# 지금 매매 규칙

지금 실제로 적용 중인 규칙들을 한 곳에 정리한다. 바뀔 때마다 여기도 같이 고친다.
"왜 이렇게 바꿨는지"의 과거 기록은 `DECISIONS.md`에 남아있다 - 이 문서는 그 결과로
지금 켜져 있는 규칙이 뭔지만 보는 용도.

**나중에 승률/손익을 시간대·규칙별로 분석할 때, "규칙 적용 전/후" 데이터가 섞이면
안 되므로(오염 방지) 각 규칙이 실제로 언제부터 라이브 거래에 반영됐는지 아래에
명시해둔다. "코드를 커밋한 날"이 아니라 "실제 매매에 처음 영향을 준 날"을 기준으로
적는다 - 이 둘이 다른 경우(예: 저녁 스크리닝 반영은 하루 늦게 시작되는 경우)가
있어서 그것도 구분해서 적는다.**

| 규칙 | 적용 시작 |
|---|---|
| 1) 눌림목 매수 전략 (dip_buy) | 2026-08-26 (그 이전 변동성 모드에서 되돌림) |
| 2) 손절/익절 시장국면 조정 | 이 기록을 시작하기 전부터 있던 기능 (정확한 시작일 불명) |
| 3) 코스닥룰 (지금 형태: 전날 종가 기준 슬롯 제한) | 2026-08-31 |
| 4) 사이드카룰 (계좌 손실 한도) | 2026-08-26 |
| 5) 사토시룰 (변동성 종목 빠른 감시) | 코드 배포 2026-09-01 21:18 / 빠른감시 루프 첫 실제 가동 2026-09-02 09:05 / 저녁스크리닝 기반 표시는 2026-09-02 15:35부터 (그 전날 저녁엔 아직 반영 안 된 상태로 9/2 아침 종목이 뽑혔음) |
| 6) 10시반룰 (매매 시작 10:30으로) | **2026-09-02 15:42 코드 반영 (2026-09-03부터 실제 적용)** |

**주의**: 5)번 사토시룰은 9/2 하루는 "루프는 돌지만 그날 아침 뽑힌 종목 5개는
아직 변동성 표시가 안 된 상태"였다 (그래서 9/2 캔버스엔 사태 때 사토시룰이
못 잡았음 - 버그가 아니라 반영 시점 문제였음). 온전히 적용된 첫날은 **9/3부터**로
보는 게 맞다.

## 1) 기본 매수 전략 - 눌림목 (dip_buy)

- 최근 며칠 고점 대비 일정 % 이상 하락 (`dip_buy_pct`)
- 그 이후 최근 저점 대비 일정 % 이상 반등 확인 (`rebound_confirm_pct`)
- 거래량이 평소 대비 충분히 실렸는지 확인 (`volume_multiplier`)
- 세 조건을 다 만족해야 매수 신호 (`strategy.compute_entry_signal`)
- 후보 선정은 매일 저녁(evening_screen.py) 자동으로, 장중엔 슬롯 하나가 비면
  즉시 재선정(screener.replace_blocked_stock)

## 2) 손절/익절

- 기준(%)은 시장 국면(코스피 20일선 위/아래, 며칠째인지)에 따라 자동으로
  조금씩 조정됨 (`market.analyze`) - 하락장이 길어지면 손절은 타이트하게,
  익절은 빨리 확정하는 쪽으로 움직임
- 상대평가 손절 옵션(`use_relative_stop_loss`) 켜져 있으면, "내 종목이 몇 %
  빠졌나"가 아니라 "코스피보다 얼마나 더 나쁜가"로 판단 (시장 전체가 무너지는
  날 혼자만 손절당하는 걸 막기 위함)
- 종목당 손실/이익 금액(원) 기준도 같이 봄 (`stop_loss_amount`, `take_profit_amount`)

## 3) 코스닥룰

- 전날(직전 거래일) 코스닥 종가가 그 전날 대비 마이너스면, 오늘 신규매수
  슬롯을 `max_positions`에서 2개로 제한 (`risk.effective_max_positions`)
- 근거: 8/4~8/28 데이터 기준, 전날 코스닥 마이너스 → 다음날 평균 승률 37.7%,
  플러스 → 81.3%
- 이미 보유 중인 종목의 손절/익절 감시는 슬롯 수와 무관하게 항상 계속됨
- 코스피, 코스닥 개인순매수, 상한가/하한가 종목수는 아직 로그만 쌓는 중
  (`market_history.csv`, `investor_history.csv`, `uplow_history.csv`) -
  검증되면 이 판단에 추가로 반영할지 결정 예정 (아래 "논의중" 목록 참고)

## 4) 사이드카룰 - 계좌 전체 손실 한도

- 오늘 실현손실이 **현재 계좌 총액(현금+보유종목 매입원가)의 `daily_loss_limit_pct`%**를
  넘으면, 그날은 신규 매수를 더 이상 하지 않음
- 고정 금액이 아니라 계좌 총액 대비 비율이라, 계좌 규모가 변하면 실제 금액
  기준도 같이 움직임 (`risk.daily_loss_limit_breached`)
- 이미 산 종목의 손절/익절 감시는 계속됨 (방치하는 게 더 위험하므로)

## 5) 사토시룰 - 변동성 종목 빠른 매도감시

- 계기: 2026-09-01 사토시홀딩스(223310) - 매수 10분 만에 -4.3% 손절, 그 사이
  장중 한때 +10%까지 갔었다는 걸 놓침 (10분 주기로는 그 반전을 못 봄)
- 후보 종목의 최근 5거래일 평균 일중변동폭((고가-저가)/종가)이 **10% 이상**이면
  "변동성 종목"으로 표시 (`volatility.py`)
  - 기준값 10%는 실제 데이터로 정함: 사토시홀딩스 12.6% vs 루닛 3.8%,
    성호전자 9.0% - 둘을 뚜렷하게 가르는 지점
- 매수 조건에는 전혀 영향 없음 - 매수는 원래 기준(위 1번) 그대로. 표시된
  종목이 실제로 보유 중일 때만 **30초 간격**으로 손절/익절 확인
  (`watch_positions.py`, daemon이 백그라운드로 같이 띄움)
- 표시는 매일 저녁 스크리닝 + 장중 슬롯 교체 시점에 갱신, 다음날 저녁
  스크리닝 때 전부 초기화 (`volatility.clear_all`)
- 계산 결과는 전부 `logs/candidate_volatility.csv`에 기록 (코스닥 지표와의
  상관관계도 나중에 검증 가능하게)

## 6) 10시반룰 - 매매 시작을 10:30으로

- 계기: 2026-09-02, 지금까지 전체 거래(72건)를 매수 시각별로 분석한 결과 -
  10:30 이전 매수 44건 승률 45.5%(합계 -140,174원) vs 10:30 이후 매수 28건
  승률 67.9%(합계 +108,906원). 1만원 이상 손실 13건 중 12건이 정오 이전 매수.
- "일찍 사고 매도 판단만 10:30부터 하면 어떨지"도 과거 분봉으로 확인해봄 -
  평균은 살짝 나아지지만(-21,210원 → -16,716원), 개별 편차가 커져서(일부는
  극적으로 회복, 모아라이프플러스 같은 경우는 -18,482원에서 -58,916원까지
  악화) 오히려 최악의 경우 손실이 더 커질 위험이 있다고 판단, 채택 안 함
- 그래서 매수 자체를 09:05 대신 **10:30부터 시작** (daemon.py `MARKET_OPEN`).
  전량정리(15:20)·저녁스크리닝(15:35)은 그대로
- 예외 슬롯 없이 전체 슬롯에 일괄 적용 (연속 손실 이후라 지금은 그 시간대를
  더 시험해볼 여유가 없다고 판단 - 나중에 여유 생기면 재검토 가능)

## 7) 그 외 항상 켜져 있는 안전장치

- **당일 재진입 금지**: 오늘 판 종목은 오늘 다시 후보로 안 뽑힘 (`sold_today.py`)
- **관망 6회차 초과 시 교체**: 매수 조건을 6회차(약 1시간) 동안 못 채우면
  다른 후보로 교체 (`WATCH_CYCLE_LIMIT`, `watch_state.py`)
- **거래 불가 종목 자동 제외+교체**: 주문이 거부되면(관리종목 등) 그 종목을
  기록해두고 다음부터 후보에서 제외, 가능하면 즉시 대체 종목으로 교체
  (`blocklist.py`, `screener.replace_blocked_stock`)
- **최근/누적 손실 종목 후보 제외**: 최근 3거래일 반복 손실이거나 전체 기록상
  누적 손실인 종목은 다음날 후보에서 제외 (`loss_cooldown.py`)
- **중복 실행 방지**: daemon 자체의 중복 실행(`daemon.lock`)과, 실제 매매
  실행 구간 자체의 중복 실행(`trading.lock`, `exec_lock.py`)을 이중으로 막음

# 논의했지만 아직 적용 안 한 것

## 카나리아 소형주 전략

- 아이디어: 슬롯을 균등하게 안 두고, 작은 "카나리아" 슬롯 1개(더 엄격한
  매수 기준, 항상 열림) + 보통 슬롯 여러 개(시장 지표 좋을 때만 열림)로 나눔
- 사토시룰보다 먼저 논의됐지만, 사토시룰이 더 구체적이고 시급하다고 판단해
  먼저 만듦 (2026-09-01)
- 보류 이유: 아직 세부 기준(카나리아 슬롯 예산 비율, "더 엄격한 기준"의
  구체적 수치)을 안 정함. 코스닥/개인순매수 지표 로그가 더 쌓이고, 사토시룰·
  10시반룰 효과가 확인된 뒤에 이어서 논의하기로 함

## 코스닥룰 조건 확장 (개인순매수/상한가·하한가 종목수 연동)

- 아이디어: 지금 코스닥룰은 "전날 코스닥 종가" 하나만 보는데, 여기에
  개인순매수·상한가/하한가 종목수 같은 다른 지표도 같이 연동해서 조건을
  더 정교하게 만들고 싶음 (2026-09-02)
- 지금은 이 두 지표 로그만 쌓는 중 (`investor_history.csv`, `uplow_history.csv`,
  3번 항목 참고) - 아직 검증된 지표가 아님
- (2026-09-02 확장) `investor_history.csv`는 원래 개인 순매수만 기록했는데,
  "장 초반엔 개인이, 나중엔 기관/외국인이 주로 움직이는 거 아니냐"는 가설을
  나중에 검증할 수 있게 외국인·기관계 순매수도 같이 기록하도록 바꿈
  (`api_client.get_investor_flows`). 이날부터 기록된 행만 3개 값이 다 있고,
  그 이전 행은 개인 순매수만 있음(마이그레이션 시 빈 칸으로 남김)
- 보류 이유: 검증 안 된 지표를 이미 검증된 코스닥 종가 지표와 같은 비중으로
  섞으면 오히려 판단을 흐릴 수 있음. 실제 데이터가 더 쌓여서 이 지표들도
  코스닥 종가처럼 승률과의 상관관계가 확인되면, 그때 코스닥룰에 조건을
  추가할지(예: 코스닥+개인순매수 둘 다 봐야 슬롯 개방 등) 논의하기로 함

## 가격룰 (매수가 낮은 종목 제외)

- 계기: 2026-09-02, 전체 거래(72건)를 매수가 구간별로 분석한 결과 -
  2천~5천원 승률 30.8%(-59,180원), 5천~1만원 승률 35.7%(-76,405원)로
  1만원 이상 구간(승률 69~78%)보다 뚜렷하게 나쁨
- 근데 시간대(10시반룰)와 교차 분석해보니 - 2천~5천원대는 10:30 이전
  승률 11%(-79,174원) vs 10:30 이후 75%(+19,994원)로, 사실상 "저가주가
  하필 장 초반에 몰려서" 나쁜 것에 가까웠음(시간대 문제와 상당 부분 겹침)
- 다만 5천~1만원대는 10:30 이후에도 승률 40%(표본 5건)로 여전히 약해서,
  이 구간만큼은 시간대로 다 설명이 안 될 가능성이 있음 - 표본이 너무 작아
  아직 결론 내리긴 이름
- 보류 이유: 10시반룰을 먼저 적용해서 저가주 문제 중 시간대로 설명되는
  부분이 실제로 해소되는지 새 데이터로 확인한 뒤, 그래도 5천~1만원대가
  계속 약하면 그때 별도 가격 기준을 만들지 판단하기로 함
