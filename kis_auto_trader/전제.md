# 전제 - 이 프로젝트가 무엇을 하려는가

(2026-09-22 신설) 사용자: "지금 전제 조건을 사람이 투자를 하는게 아니라
AI가 자동투자를 해서 얻는 이점을 살려야 한다는 걸 명백히 했으면 해"

이 문서는 **목표**를 못 박는다. 결과(`결론.py`)나 규칙(`RULES.md`)과 다르다.
앞으로 무엇을 재고 무엇을 채택할지가 여기서 갈린다.

---

## 전제

> **사람이 투자하는 게 아니다. AI가 자동으로 투자한다.**
> 그러니 **자동화만이 할 수 있는 일**에서 이점을 찾아야 한다.
> 사람이 똑같이 할 수 있는 전략은, 이 프로젝트의 답으로서는 미완성이다.

사용자가 이 전제를 꺼낸 계기는 정당한 지적이었다.

> "네가 추천해준것도 결국 사람이 하는 게 더 나은 거였으니."

맞는 말이다. 지금 전략(저변동 10종목 / 120일 / 부분교체)은 **1년에
주문일이 2번**이다. 달력 알람만 있으면 사람이 그냥 한다.

---

## 가장 중요한 단서 - 전제는 '어디를 볼까'이고 '무엇을 채택할까'가 아니다

이걸 섞으면 프로젝트가 망한다.

| | |
|---|---|
| 전제가 정하는 것 | **어디를 찾을까** (탐색 방향) |
| 전제가 정하지 않는 것 | **무엇을 채택할까** (채택 조건) |

채택 조건은 그대로다. 사전 등록 → 시작일 → 반띵 → 대조군 → 연도별 지속성.
"자동화 이점을 쓴다"는 것이 **채택 이유가 될 수는 없다.**

왜 이 단서가 필요한가. 실제로 이런 게 있었다.

```
1일 주기 교체   백테스트 연 25.1%   <- 자동화만 할 수 있는 일이다
                반띵 뒤집힘 (전반부에서 기준에 짐)
                슬리피지 0.08% 에서 역전
                낙폭 -15.9% -> -18.8%
```

"매일 갈아타는 건 사람이 못 하니까 이게 우리 답이다"라고 하면, **가장
자동화다운 것을 채택하면서 동시에 가장 확실하게 지는 길**로 간다.
전제는 그 함정을 막기 위해서도 필요하다.

---

## 자동화 이점을 다섯 갈래로 갈랐다

### (A) 확실히 이기는데 **안 보이는** 것 — 선정

1,813종목의 60일 변동성을 매일 계산해 순위를 매기는 일. 사람은 못 한다.
이게 **63.5%p**를 만든다 (`analyze_styles.py`: 고변동 -41.5% vs 저변동
+22.0%).

주문일이 2번뿐이라 눈에 안 보인다. 그런데 **그 2번의 결정을 만드는 계산이
전부 여기 있다.** 사람이 "안정적으로 보이는 종목"을 눈으로 골랐다면 이
결과가 안 나온다.

그리고 순위 구간을 잘라보면 한 칸만 밀려도 절반이 날아간다
(`analyze_styles.py --slice`: 1~10위 22.0% vs 11~20위 11.0%).
즉 **정확한 계산이 이점의 본체다.**

### (B) 확실히 이기는데 **안 하는** 것 — 규율

| 사람이 하고 싶어지는 것 | 결과 |
|---|---|
| 오르면 판다 | 12/12 짐 (`analyze_original`) |
| 손절한다 | 낙폭도 못 줄였다 (`analyze_stops`) |
| 나쁜 날은 쉰다 | 23가지 전부 짐 (`analyze_timing`) |
| 종목을 5개만 집중한다 | 10종목에 4/4 짐 (`analyze_original`) |

사람은 반드시 개입한다. 기계는 안 한다. 이건 '무엇을 하는가'가 아니라
**'무엇을 안 하는가'**로 나타나는 이점이다.

### (C) 이점처럼 보이는데 **데이터가 아니라고 한** 것 — 계속 보고 반응하기

타이밍 23가지, 지표 14개, 합의/계단식, 이벤트 교체, 짧은 주기 — 전부
탈락했다. 이유가 중요하다. **신호가 없어서가 아니라 수수료 때문이다.**

```
순엣지(H) = 하루당엣지(H) x H - 수수료 x 교체비율
하루당 엣지 0.093%, 왕복 수수료 0.21% -> 손익분기 2.3일
```

1일 보유는 엣지가 +0.102%로 살아 있는데도 연 -27.0%다. 더 봐도 더 벌리지
않고, 더 거래하면 더 잃는다. **이 갈래는 이 프로젝트에서 닫혀 있다.**

수수료의 86%가 증권거래세라 깎을 방법도 없다 (2.3일 -> 1.9일).

### (D) 아직 안 재본 유일한 자리 — 장중

10분봉을 2026-09-22부터 모으고 있다 (`fetch_intraday.py`). 이 저장소가
타이밍에서 23가지를 놓쳤지만 **그건 전부 '날' 단위**였다. **하루 안의
시간대는 데이터가 없어서 한 번도 못 봤다.**

채점 기준은 데이터가 한 줄도 없을 때 미리 박아뒀다
(`analyze_min10.py`, 커밋 순서가 git log에 남아 있다).

먼저 답할 것: **수수료를 넘을 수 있나.** 10분 구간 변동폭 추정 0.93%,
왕복 수수료 0.21% → **구간 변동폭의 23%를 먹어야 본전.** 어느 보유시간
에서도 순수익이 양수가 아니면 조건 찾기를 그만둔다.

20거래일이면 그 판정이 나온다.

### (E) 거래 없이 감시하기 — 수수료가 0이라 (C)의 함정에 안 걸린다

`monitor.py`. `analyze_why.py`가 분해한 세 숫자를 최근 창으로 다시 계산해
**"전략의 전제가 아직 성립하나"**를 매일 본다.

```
구간             상승/하락  하락포착  상승추종  남은엣지%p
전체 (2021~)       1.061    0.229    0.369    +115.7
최근 120일         1.052    0.104    0.250     +12.4
그 앞 120일        1.727    0.423    0.460     -14.5   <- 셋 다 경보
```

그 앞 120일 구간은 셋 다 경보였다. **그 구간에 이게 있었다면 "지금
불리한 국면"을 매일 알려줬을 것이다.** 사람이 매일 이 셋을 계산할 방법은
없다.

**이건 예측이 아니다.** 예측은 23가지 시도해서 전부 실패했다. 이건 "지금
어떤 국면이고 전제가 아직 성립하나"만 말한다. 둘은 다른 일이고, 뒤쪽은
수수료가 들지 않는다.

## 그래서 지금 상태를 전제에 비추면

| 갈래 | 상태 |
|---|---|
| (A) 선정 계산 | **쓰고 있다.** 이점의 본체. 다만 눈에 안 보인다 |
| (B) 규율 | **쓰고 있다.** 주문 함수가 코드에 아예 없다 |
| (C) 계속 반응 | **닫혔다.** 수수료가 구조적으로 막는다 |
| (D) 장중 | **수집 중.** 20거래일이면 1차 판정 |
| (E) 감시 | **켰다.** `매일 실행.bat` STEP 9/9 |

사용자 지적에 대한 정확한 답: **(A)와 (B)는 이미 자동화 이점이다.
그런데 그게 "하루 2번 주문"으로 보이니 이점처럼 안 느껴진다.**
느껴지는 이점은 (D)와 (E)에서 나온다. (E)는 켰고 (D)는 재는 중이다.

## 앞으로 재는 것이 전제를 지키는지 확인하는 질문

새 아이디어를 재기 전에 이 셋을 먼저 답한다.

1. **사람이 이걸 할 수 있나?** 할 수 있으면 자동화 이점이 아니다.
   (그래도 이기면 채택한다 — 전제는 채택 조건이 아니다.)
2. **거래를 늘리나?** 늘리면 (C)의 함정이다. 수수료를 먼저 계산한다.
3. **어느 갈래인가?** (A)~(E) 중 어디인지 적는다. 어디에도 안 들어가면
   왜 그런지 적는다.

## 실패로 남긴 기록

전제를 세우면서 같은 날 두 가지를 헛디뎠다. 둘 다 남겨둔다.

**1) 종목을 많이 담으면 자동화 이점이 아닐까 — 측정이 오염돼 있었다**

"사람은 100종목을 못 관리한다. 기계는 한다. 그리고 부분교체라서 거래도
안 늘어난다" — 전제가 여는 좋은 질문이었다. 그런데 돌려보니 10종목이
연 **-21.6%**로 나왔다. 확립된 값은 +22.0%다.

원인은 전략이 아니라 **데이터 한 줄**이었다. 그날 08:36(장 시작 전)에
수집이 돌아 `20260922`가 573종목만 들어왔고(전날 1,712종목), 그게 패널의
마지막 날이 되자 보유 종목 대부분이 가격을 못 찾아 평가액이 현금 수준으로
주저앉았다.

`strategy.load_panel()`에 `_drop_incomplete_tail()`을 넣어 막았다. 분석
모듈 30개가 전부 여기를 지나가므로 한 번만 막으면 된다. 버릴 때는 반드시
화면에 적는다 — 조용히 버리면 "왜 어제 숫자와 다르지"를 헤맨다.

고친 뒤 +22.3% / -15.9%로 복구됐다. **종목 수 질문은 아직 안 답했다.**
오염된 측정으로 답을 적지 않는다.

**2) 10분봉 첫 수집이 전부 빈 봉이었다**

같은 08:36 실행에서 분봉도 6,000행을 받았는데 거래량 0, 시=고=저=종이
100%였다. 장이 안 열렸으니 API가 전일 종가로 채운 것이다. 날짜가 오늘로
찍혀서 마감 후 재실행 시 중복으로 걸러질 뻔했다 — 첫날을 통째로 잃을
상황이었다. `is_placeholder()`로 막고 6,000행을 걷어냈다.

두 사고의 공통 원인이 하나다. **장 시작 전에 수집을 돌렸다.**
